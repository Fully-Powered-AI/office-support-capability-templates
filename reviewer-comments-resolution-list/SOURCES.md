# Sources and credits

Written by Fully Powered AI in its own words. The method draws on one open-source package written for lawyers, LegalQuants/lq-skills (Apache-2.0): its main instructions for gathering comments and tracked changes from several reviewer copies of one draft into a checklist that is never merged, with each item kept under its reviewer (named unless the user asks for reviewers to be anonymised) and given a confidence for where it sits, anything that cannot be read reliably (a table, a text box, a footnote) marked for checking by hand, every item given a status that starts open and a note for the owner's decision, a stop when the base is unclear, a request for the files when none are supplied, and clashes, unlocated comments and a separate list of high-risk changes (dates, figures, whole-paragraph changes and formatting-only changes) set apart; its reference notes for the narrow meaning of a clash, two items that cannot both be carried out; and its example output, which counts the items taken from each reviewer. Fully Powered AI rewrote the work for any business document and added a separate list of agreements, where reviewers propose the same change, the default export columns with a stop when an export's headers differ, emailed and spoken notes split into single requests, a watch list the owner sets, with names and promises about future work added, a naming rule the owner sets, the earlier-version question, the rules for placing and ordering items, and the later run that records the owner's decisions, recounts and lists the accepted edits. No third-party text is reused.

A checklist built from several reviewers' comments and tracked changes on one draft and never merged into it: each item kept under its reviewer, named unless the user asks for anonymity, with the exact words proposed, placed against the base with a confidence for its location, grouped by section, and given a status (open by default, then accepted, rejected or deferred) and a note for the owner's resolution; anything that cannot be extracted reliably, such as a table, a text box or a footnote, kept in the list as an item to check by hand; clashes, unlocated comments and a separate list of high-risk changes (dates, figures, whole-paragraph insertions or deletions, and changes to formatting alone, which can carry a change of meaning) called out apart; the stop when the base is unclear; and a request for the files or pasted comments, instead of a claimed collation, when none are supplied.
